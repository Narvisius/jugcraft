# Companion kitchen jobs and nine-output filters

Owner-requested 8 October 2026, implemented locally on `peepo-companion` by OpenAI Codex (GPT-6). Extends the existing jobs, physical Supply/Output transport, farmhouse kitchen recipes and vanilla-style companion menu. No new platform, dependency, recipe, texture or currency.

## Setup

Assign a Cutting Board, Skillet or Kitchen Stove with the Companion Planner. Assign Supply and Output containers, select Work, and leave reachable space beside each station. Put a knife in the companion's Hand slot for cutting. Heat the Skillet from below; light the Stove manually and keep its top clear. An occupied stove top remains a heat source for the pot/skillet above; the stove's own hob does not cook through those blocks.

Each recipe-capable workstation row now has an **F button with the tooltip Filter**. It opens nine ghost slots in a 3 by 3 grid inside the same inventory. Click with an output item to permit that output; right-click or click with an empty cursor to clear a slot. Real cursor items are never consumed. Empty filters permit any available recipe. A Hearth Oven also accepts raw icons and normalizes them to baked outputs. The garden's crop/seed selector is unchanged: it is a planting selection, not a production recipe.

Filters apply to Cooking Pots, recipe-capable standard processors, Hearth Ovens and the three kitchen stations. Existing single recipe selections initialize the first filter entry. Filters are saved on the workstation, shared by its helpers, and independent of assignment order. The selected processing/supply recipe is now an internal batch choice; the filter slots are allowed outputs, not a crafting pattern or priority list. Multiple recipes for the same output can be selected according to available ingredients. Clearing all entries restores Auto. Clearing a filter does not discard existing ingredients or completed goods. Pot/machine filter edits reset their recipe progress as previous recipe edits did; an already loaded oven/skillet/stove bake finishes normally.

## Kitchen jobs

- **Cutting Board:** one input at a time; one claimed helper uses the [two-handed CHOP clip](companion-kitchen-animation.md) with its full-size equipped knife for 40 ticks per cut. It approaches the board's facing side. Uses the existing cutting recipe and knife tool predicate. A completed cut costs up to 16 JE and one actual knife durability, and preserves every recipe result/byproduct. Knife wear is written back to the companion's real Hand inventory, not just its equipment display. An output filter may match any result of a cut. No cost is charged merely for waiting. Nine saved result stacks hold finished cuts until Output collection; no cut starts unless all results fit.
- **Skillet:** real raw capacity remains 16, one item variant at a time. The existing heat requirement, cooking time and fried-output stack remain authoritative. Supply loads compatible raw food; Output extracts only fried food and leaves uncooked food/progress alone. Input demand reserves enough potential fried space for loaded food. No speed bonus or resident helper is added.
- **Kitchen Stove:** six existing cooking positions, ordinary cooking speed, lit state and clear-top requirement remain. Companion-loaded positions retain a saved managed marker. When done, their real results enter a nine-stack saved collection buffer; a full buffer pauses completion without consuming/losing food. Buffer retries are paced to once per second. Manually loaded positions retain the original loose-drop behaviour. Empty-hand use retrieves the managed results, and breaking the stove drops them normally. Stove cooking does not consume fuel in the existing implementation; no new fuel rule is invented here.

Both heating jobs use the existing porter movement/energy costs and can be left cooking while the companion handles another assignment. Supply/Output On/Off controls, priorities, rest, meals, owner/party settings and menu pause are retained. Manual empty-hand board use can retrieve buffered cuts. Removing the companion never destroys buffered products.

## Recipe choice, transactions and multiplayer

Before an admitted supply search, Cooking Pot and processor ports inspect at most 128 extractable source views in a rollback transaction, then consider at most 256 recipe candidates. They consider existing inputs and one complete batch's ingredient counts; matching is conservative for overlapping ingredient tags. Recipe catalogs use existing cached infrastructure. Fluid recipes also require their declared fluids to be present; Peepo does not transport fluid through item slots. Selection is not repeated every entity tick or every source view. Empty stations do not retain a stale supply plan when no complete candidate is available. Existing partial inputs may keep their plan so they can be completed later.

Kitchen input/output changes and companion cargo participate in the same Fabric transaction. Rollback restores raw items, cooked items, timers, managed hob flags and output buffers. Cutting reserves all output capacity before consuming the board item and energy. Actual knife wear follows the successful server-side cut. Output filters restrict new supplies/cuts, not rescue of completed output.

Menu updates retain the original 46 real inventory/equipment slots. The four legacy preview positions remain for seed compatibility; nine non-pickup ghost slots are appended. The server validates owner/party permission, menu distance, loaded target, assignment identity, town/lock permission, edit rate, output recipe and slot range. Filter editing has no generic client item-creation packet. Drag, shift-click, swap, throw and creative clone cannot turn ghosts into real items. If another viewer reorders/removes the assignment or the workstation unloads, the editor closes/rejects stale edits. The same menu stays open, preserving companion pause and cursor inventory ownership.

Update both client and server together for the expanded menu data/slots. All processing remains server-authoritative. Existing searches, path budgets, timeout/backoff and loaded-only checks apply. Cutting readiness caches recipe/capacity checks for up to one second, invalidated by item/tool/filter changes and committed transfers. One lease per Cutting Board; no fake players, global workstation/entity scan, remote inventory transfer or chunk tickets. Existing station art is reused; no owner-library assets are copied or changed. The initial general clip was subsequently replaced by the dedicated chopping animation linked above.
