# Acid factory and Encyclopedia — local playtest

Owner-selected sequence, 12 October 2026: finish starter acid processing, then build the Jugcraft Encyclopedia. Implemented with OpenAI Codex (GPT-6 family), on the existing local starter-chemistry playtest branch. Owner review precedes any push or merge.

## Acid factory

The existing Chemical Reactor now accepts a liquid feed, absorption gas, and a separate retained acid charge, with its original product output. It preserves all original recipes and its 2×2×2 model. Side/bottom connections serve ordinary feeds and output; the top prioritizes the dedicated carrier, then retains normal transfer support. Use one sulfuric-acid bucket on top to commission the sulfuric line. Do not continuously pipe acid into a water-feed reactor after its carrier is full: overflow can fill the ordinary liquid feed.

| Game process | Consumed inputs | Output | Retained charge | Work |
| --- | --- | --- | --- | --- |
| Hydrogen chloride absorption | 500 mB water + 500 mB hydrogen chloride gas | 1000 mB hydrochloric acid | None | 100 ticks × 96 JE/t |
| Sulfur trioxide absorption | 250 mB water + 250 mB sulfur trioxide | 500 mB sulfuric acid | 1000 mB sulfuric acid | 100 ticks × 96 JE/t |
| HCl copper recovery | 1 raw copper + 250 mB hydrochloric acid | 1 washed copper | None | 160 ticks × 96 JE/t |

These are game balance receipts, not real chemical procedures. The first carrier comes from the existing sulfur/water recipe or trade. The Oxidizer and Infuser supply the sulfur gases; the Infuser combines electrolytic hydrogen/chlorine for HCl. Sulfuric acid feeds existing fertilizer, ore recovery, plating, electronics and electrolyte recipes. No new machine, ore, catalyst or advanced material is required to start.

The reactor checks inputs, retained charge and output capacity before spending work or completing a batch. Input storage refuses extraction; the retained acid never enters output accounting. The dropped reactor carries only the retained charge through the existing stored-fluid item component. Ordinary process tanks still need draining before breaking. Layout 1 migrates old input 0 to input 0 and old output 1 to output 3; new gas/carrier tanks start empty. No free startup charge, lost old product, or output-to-input migration.

Fluid recipes gain an optional `retained` input flag, default false and serialized to clients. Existing recipes retain their behavior. Form machines explicitly reject retained-input recipes until their escrow supports them. JEI labels the retained charge as a reusable requirement. The existing procedural fluid art generator authors the new acid's bucket and liquid textures; no external images are copied.

## Encyclopedia

Open with remappable **K**, the **Jugcraft guide** inventory button, or a saved Engineer's Handbook. No carried item or recipe is required. The old handbook item registration remains intact as a shortcut. Detail pages have a return button; closing the guide returns to the originating inventory when applicable.

The original native screen indexes canonical handbook and Concordance codex content, plus exact installed-build fluid-process references and new start/acid guides. It provides Home, Technology, Magic, Goals and Routes, search across unlocked text, chapter drill-down, bounded result paging, back history, tooltips, native keyboard-focusable controls, two branching route diagrams and adjustable route spacing. Route edges are explicitly suggested connections, not exact recipe dependencies or research prerequisite graphs.

Quest policy: optional, individual advancement-backed goals, no rewards or consumption, no shared-party completion, no forced progression gates. Existing completion stays valid. Existing objective semantics are preserved; five new obtaining objectives accept possession observed by normal inventory-change events, including trade. Items acquired and lost before installation cannot retroactively count. These objectives do not require crafting specifically.

The server sends read-only completion snapshots on opening/refresh, rate-limited to one per second, at most 512 goals. Requests contain no player identity, reward claim, arbitrary advancement ID or completion instruction. The catalog reloads with server datapacks and has a 1 MiB bound. Vanilla advancements remain the only persistent completion store. No new currency or save format. Client snapshots clear on disconnect. Missing advancements show unavailable rather than completed. Magic detail pages preserve codex research gates; guide reading never grants research.

Content is generated by `tools/encyclopedia.py` through the existing material generator. Recipe references describe installed resources, not arbitrary server recipe overrides. The UI reuses the native Handbook detail renderer and existing canonical icons; it adds no mandatory optional-library dependency and no copied reference-screenshot artwork.

## Acceptance boundaries

This is a working first Encyclopedia delivery, not a claim that every requested future school or industrial specialty is implemented. Further editorial refinements, translated guide prose, bookmarks/pinned goals, a fully spatially zoomable/pannable graph, richer activity-specific quests and any reward/party policy are follow-ups. The old Handbook detail layout is reused rather than a wholesale custom graph-and-detail renderer. Machine art, first-survival progression time and human multiplayer balance still require owner playtesting.

The acid slice completes the missing wet absorption/carrier integration. It does not implement map-wide pollution, larger industrial variants, purity grades or the remaining industrial roadmap.
