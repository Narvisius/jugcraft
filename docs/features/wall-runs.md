# Pipes and cables in walls

Status: implemented; covered by gametests, not yet tested on a dedicated server
Proposal issue: none (requested in Justin's round 12 of nuclear plant work; idea from RimWorld's hidden conduits)
Owner: Narvisius
Target milestone and tier: any tier that has the mod's pipes and cables
Primary specialty and supported player role: building and infrastructure; tidy bases where pipes and cables run
inside walls, floors and ceilings

## Player experience
Pipes and cables can run **inside** a made wall instead of across its face, the way RimWorld hides conduits.

- **Putting a run in a wall.** Hold a pipe or cable and sneak-right-click a made block (concrete, bricks, planks,
  metal and other full, solid, opaque, plain blocks). The block becomes that run inside the wall.
- **Putting a wall round a run.** Hold a made block and sneak-right-click a pipe or cable already laid. The block goes
  round it.
- **The wall keeps its look.** The client draws the wall's own block model, so any block (vanilla or modded) works
  without textures of its own. The run is as solid as the wall and as hard to break.
- **Sleeves.** Where a run comes out of the wall into the open (joined to a pipe, cable or machine not itself in a
  wall), a wall sleeve shows on that face: a bolted plate and a collar round the pipe, or a conduit fitting with a
  lock nut for a cable. Inside the wall nothing shows.
- **Seeing hidden runs.** While a pipe, a cable or the brass wrench is in hand, runs hidden in walls within 20 blocks show
  through the walls as faint lines: fluid pipes blue, item pipes amber, cables orange.
- **Taking a run out.** Sneak-right-click with the brass wrench, or Ctrl + right-click holding any block, pulls just
  the pipe or cable out and leaves the wall. Breaking the block drops both the wall's block (if the tool would have
  dropped it) and the pipe. Pick-block gives the wall's block.
- **Blueprints.** A run placed by a blueprint build without a known wall takes the look of the commonest made block
  around it a tick later (smooth stone if none).

Carriers: Bronze Fluid Pipe, Steel Fluid Pipe, Brass Item Pipe, Copper Cable, Silver Cable, Aluminum Cable. A run in
a wall carries exactly what the plain pipe or cable carries, at the same rate, and joins the same neighbours.

Natural ground and rock are never walls for a run (tag `jugcraft:wall_run_excluded`: dirt, overworld and nether base
stone, nylium, ores, end stone, clay, snow, mud, sculk, moss, packed mud, dripstone, calcite, smooth basalt, magma,
soul soil, bedrock). Falling blocks, blocks with an inventory, see-through (glass), light-giving and unbreakable blocks are left out by the code.

## Connections
- Existing input producer: the mod's fluid pipes, item pipes and cables.
- Existing output consumer: whatever those pipes and cables already feed.
- Technology connection: none new; uses the existing pipe and cable tiers.
- Magic connection: none.
- Reachable entry path: available as soon as the player has any pipe or cable and a made block.
- Required vs optional: optional; plain pipes and cables still work everywhere.
- For infrastructure/cosmetics: this is building infrastructure; it adds no resource links and no recipes.

## Balance and automation
No new recipes and no new costs: the player spends the pipe or cable and the block they would have placed anyway, and
gets both back when the run is broken. Rates are the plain carrier's, so there is no duplication or conversion path.
The wrench's pull-out gives back only the pipe and leaves the wall block in place, so nothing is created.

## Multiplayer and persistence
The server does every change and respects `mayUseItemAt` (spawn and claim protection); the client only sends the Ctrl + right-click pull request (`wall_run_pull`), which the
server checks (not a spectator, chunk loaded, within 8 blocks, a block in hand). The wall's look is saved in the
block entity and synced to clients. A run whose look is missing (a blueprint build) picks one from its neighbours.
Removing the mod leaves the run blocks missing like any removed block.

## Dependencies and assets
No new dependencies. Sleeve models are generated by `tools/wall_runs.py` from existing textures (`dp_gunmetal`,
`dp_chrome`, `st_galv`); lang, loot tables and tags come from the same script.

## Verification
- `WallRunGameTests.pipeRunsThroughAWall`: natural blocks are refused and made blocks accepted; a steel pipe through
  bricks keeps the bricks' look, is a full block, joins its neighbours on the right sides, keeps the plain pipe's rate,
  drops the bricks and the pipe, and Ctrl + right-click pulls the pipe out and leaves the bricks; a cable goes into a
  wall the other way round.
- `WallRunGameTests.builtRunTakesTheWallsLook`: a run placed with no look takes the stone bricks round it.
- Planned, not yet done: a dedicated-server check with two clients (one placing runs, the other seeing the walls'
  looks and the overlay).

## World and event applicability
Not applicable: this is a building feature with no world generation, mobs, loot or seasons.

## Rollout and open questions
- The see-through overlay has a fixed 20-block range; large bases may want a toggle later.
- Only the six carriers above have wall runs; new pipes or cables need an entry in `WallRuns.WALL_OF` and
  `tools/wall_runs.py`.
- Reversible: pulling every run out restores plain walls and pipes.
