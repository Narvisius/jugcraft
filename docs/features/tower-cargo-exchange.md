# Drone Tower cargo intake

The 9 October [large-input revision](tower-large-inputs.md) adds a 9-wide, 6-deep, 5-tall variant for new placements and new layout-5 towers. This record retains the original enclosed 60-part variant and its validation evidence.

Owner-requested revision by OpenAI Codex (GPT-6), 8 October 2026. The owner requested a closed cargo machine in the tower's black, charcoal, neutral-gray and concrete palette. The supplied machine examples establish the desired detail level. This revision replaces the earlier exposed-roller prototype with purpose-built enclosed logistics equipment.

## Machinery and operation

The intake is a closed armored box on a mineral-gray plinth, with fitted service covers, hinges, latches, fasteners, ventilation and an integrated front instrument bank. The item pipe enters a collar seated into the solid front bulkhead. There is no exposed conveyor, roller deck or inspection tunnel. Static mechanical detail does not add another inventory or invent an item transit phase.

The operator display reads the linked tower's actual cargo summary: stored item count, occupied inventory slots and request status. The server builds this small summary from the existing packager when preparing the terminal's normal snapshot. Old snapshots show unknown inventory readings, and unavailable endpoints suppress stale figures. Test supply is identified explicitly. Occupied slots are not treated as a fixed item capacity because stack limits vary by item.

The shared exchange renderer dispatches to separate power and cargo presentations. The existing power renderer and its artwork remain intact. Cargo displays use exact terminal/core/depot identity and loaded packager positions; they do not search for a nearby depot or read a client-side copy of the inventory. No new machine ticker, item buffer, network request stream, chunk loader or per-frame inventory scan is introduced.

## Connections and compatibility

The `cargo_exchange` ID, item, recipe, 60-part 5-by-4-by-3 footprint, part numbering, rotation and tower anchors remain stable. The real port is part 22 at canonical cell `(2,1,0)`, with its six-pixel pipe connection centered at model coordinates `(40,24,0)`. The neck reaches the block boundary at `z=0` and continues into the housing, closing the old installed socket's 5.4-pixel inset gap. The original 27-slot Cargo Packager remains the only inventory. Jugcraft's brass item pipe, wall-run brass item pipe, extractors and compatible Fabric item storage feed that store through the marked outward face; drones take and return their construction materials there. Closed service covers do not add extra intake faces.

The existing steel-plate, intake-funnel, advanced-circuit and Cargo Exchange Port recipe remains reachable through the established technology progression. Ownership, formation, transaction rollback, menu access and stale-handle checks remain server-authoritative. Breaking the machine still returns one kit and preserves the linked packager's materials. Tower construction data and layout versions are unchanged; existing Cargo Exchanges receive the revised appearance through the normal launcher update and restart.
