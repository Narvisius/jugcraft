# Companion fishing

Owner-requested implementation, 24 October 2026, with OpenAI Codex (GPT-6).

## Player outcome

Peepo and Jughead can fish from an explicitly chosen dry shore or dock seat. The Planner's Fishing mode records the seat first, then source water at a horizontal distance of 1–10 blocks and no more than three blocks below. A clear cast and full, safe top surface are required. The assignment uses one existing job slot and the existing priority, rename, Supply/Output and Tools controls. It has no recipe filter. Selected assignments display both endpoints and a connecting line.

The real Hand rod is required and can be fetched/replaced through stocked Tools-enabled Supply containers. Existing Hand lock and Supply Off are respected. Catches occupy the existing eight cargo slots, with job provenance and existing Output routing. Eight catches per batch, or low cargo space, ends a session for delivery. Linked Output capacity is probed transactionally; blocked output pauses further catches. Unassigned/disabled Output leaves cargo for manual collection. Existing delivery energy applies.

The native fishing loot table supplies catches, including data-pack modifications. An unspawned FishingHook supplies the correct entity predicate and location context without a fake player. A bounded source-water/open-air check determines open-water eligibility, which cannot be regained during a cast once lost. Lure reduces waiting time, rain and sky access affect the countdown, Luck of the Sea supplies loot luck, and normal rod damage handles Unbreaking. Catch XP may repair a Mending rod but creates no XP orbs. Player-activated magic rod powers are not invoked. Waiting uses the native 100–600-tick base plus 20–80-tick approach interval, subject to Lure/weather; the NPC also has explicit cast, bite and reel phases.

Fishing costs 1 reserve JE/t throughout, plus 2 JE/t during its 20-tick cast and 20-tick reel (80 extra JE per completed cycle). Interrupted work pays only for elapsed work. The seated pose does not grant chair regeneration. Rest, food, commands, editing pauses and live owner/town permissions remain authoritative; mob-griefing disables the job.

## Animation and framework integration

The existing procedural companion animation pipeline supplies four appended clips: cast, wait, bite and reel. Both hands hold the equipped rod at 85% of its native size, feet kick beyond the dock edge, and casting/reeling use body lean. The rod, upper-hand spacing and line attachment use the same scale. The seat targets a point 0.02 blocks inside the selected block's edge in the cast direction, including diagonal casts, with a 0.05-block arrival tolerance; the existing safety/path checks validate that actual point. A client-only line and bobber follow the selected water target and the synchronized clip start time. The item is read from synchronized main-hand equipment, not unsynchronized cargo. The bobber reuses Minecraft 26.3's `textures/entity/fishing/fishing_hook.png`; no library asset copies, dependency changes, fake players or spawned/ticking bobber entities are introduced. The existing model and vanilla rendering APIs are sufficient for this addition.

## Multiplayer and persistence

Each companion retains at most its four assigned fishing jobs. Loaded-only environment and aggregate Output checks run at most once per second under the existing shared search budget. Normal path budgets handle travel. A bounded weak level-keyed seat lease allows one helper per seat, with UUID ownership and expiry; distinct seats can share a pond. No pond-wide/entity searches, chunk tickets or independent production ticker are added.

Loot is rolled only when a reel completes. Already-landed overflow is persisted separately from cargo and retried transactionally; there is only one pending catch and no further cast while it is pending. Saving/loading, leaving work, changing rods or blocked cargo cannot reroll that catch. Removing the assignment returns pending catch items to ordinary cargo when space becomes available; death drops pending items. Existing marked cargo and in-progress deliveries keep their established persistence. Exceptional loot lists above 64 stacks spill excess as real drops instead of silently deleting items. Incomplete casts restart after an interruption/reload; they have not rolled loot yet.

The target schema adds an optional water position, preserving old assignment constructors and saved data. Job/status animation values are appended. Native block recipe selection/automation on the seat block cannot override the fishing job's own controls.
