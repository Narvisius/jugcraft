# Companion Candy Kettle

Owner-requested integration on 11 October 2026, implemented with OpenAI Codex (GPT-6) on `peepo-companion`. Extends the existing Discovery-tier Candy Kettle, candy stages/base/flavor rules and real Candy Tray component. Uses Fabric transactions and the existing companion Planner, nine-item Filter, Supply/Output routes, multi-stack cargo, shared search/path budgets, protection checks, energy and general two-arm work animation. No new assets, dependencies, items, currencies or recipes.

## Workflow, progression and costs

Sugar from farming, bottled water or milk from Livestock Management, and a crafted reusable Candy Tray produce the existing candies. Finished items serve food, candy bowls/bags and the kitchen recipe chain. All ten kettle candy types are supported, including four timed taffy pulls, sticks consumed per lollipop, normal five-second setting and 24,000-tick rock crystallization. A single automatic candy-corn layer is supported; layering remains manual. Up to two tagged flavors and one dye per batch may be supplied. Filter ghosts select item IDs, not flavor/color components.

A blank filter tries supported outputs with complete available inputs, preferring Hard Candy then Fudge; multiple choices are alternatives, not round-robin quotas. Planning is bounded to the existing supplied-storage scan and ten kinds, never a per-tick source scan. A plan pins once staging begins. Sugar batch size is up to four according to available sugar, and for lollipops available sticks. Missing inputs remain real staged stacks instead of entering the heated kettle prematurely. Once present, a helper starts one complete batch, tends it, pours its actual temperature-stage result, finishes its real tray and leaves the tray for reuse. Operation costs an exact 4 reserve JE per active tick, plus the unchanged load-based delivery cost. Passive tray setting and empty-kettle cooling require no operator or energy.

## Multiplayer and persistence

The eleven fixed inventory slots hold seven staged inputs/tool slots (base, sugar, tray, sticks, two flavors, one dye) and four output slots. Snapshot rollback deep-copies only this bounded inventory; speculative supply never changes the real kettle, plays sounds or advances processing. Work preflights output room/remainders before exact energy debit, then mutates on the authoritative server thread. Water/milk and optional ingredient containers are preserved, as are candy color/flavor/effect components. Existing heat mechanics and timing are not accelerated. No additional world ticker, worker scan, fake player or chunk loading is introduced. Block readiness is invalidated on actual mutations; ordinary temperature changes retain the kettle's existing sync behavior.

A single expiring helper lease and live permissions prevent concurrent cooking or remote work. The generic approach reuses eight bounded adjacent/one-block-lower standing candidates, hazard checks, path failure memory and periodic clearance checks. The kettle is explicitly non-pathfindable. The shared job interface has a default-false time-critical hook: only a Candy Kettle actively heating/pouring or pulling warm taffy uses it, suppressing ordinary transport and priority preemption during that operation. Commands, access loss, eating/rest, energy limits and cancellation remain authoritative. Other existing jobs retain the prior scheduling behavior.

Inventory, filter, plan, intended tray type and active batch identity are saved. A poured tray uses the existing immutable CandyBatch component/time/pull count; an interrupted partial pull restarts. Earlier saves default to empty staging and no plan. Filter changes return unused staging through Output before replanning; live batches finish honestly. Explicit cancellation/unattended heating can overcook, and warm taffy can harden; returned items reflect actual existing rules, not the requested filter type. Full outputs preserve real items, block the next batch, and use existing hauling recovery. Manual pouring/tipping works as before. Shift-empty-hand use on an empty kettle recovers stored items without losing inventory overflow; breaking drops staging, tray and output, while poured syrup follows existing break-loss behavior.
